Activity Log System
Implementation Guide

A robust, self-contained audit trail system for Laravel applications, designed for ultimate portability and deep integration.

Overview

This system tracks every significant event in your application. Whether it's a model change (CRUD) or a custom system event (Login/Logout), the Activity Log Service captures the context, the causer, the subject, and the exact changes made.

🚀 Portable

Everything (Model, Migration, logic) is in one directory. Copy and paste to any project.

⚡ Automatic

Hook into Eloquent events with a simple Trait. No extra code needed in controllers.

Setup

To activate the system in a new project:

  1. Register the provider in bootstrap/providers.php:
    App\Services\ActivityLog\ActivityLogServiceProvider::class,
  2. Run the migration:
    php artisan migrate

Automatic Logging

Simply add the LogsActivity trait to your model to track Creation, Updates (with diff), and Deletions.

namespace Modules\Admins\Models;

use App\Services\ActivityLog\Traits\LogsActivity;

class Admin extends Model {
    use LogsActivity;

    // Optional: Set category (defaults to 'admin')
    public string $activityLogType = 'admin';
}

The system automatically calculates the Diff between old and new values for every update, ignoring sensitive fields like passwords.

Manual Logging

For events like Login, File Downloads, or Export requests, use the manual helper:

use App\Services\ActivityLog\ActivityLogService;

ActivityLogService::log(
    action: 'exported_data',
    description: 'User exported the sales report',
    subject: $report, // Optional
    properties: ['format' => 'xlsx', 'filters' => $filters], // Extra data
    type: 'user' // Optional categorization
);

Filtering & Retrieval

Retrieve logs programmatically through the service with full filtering support:

$service = app(ActivityLogService::class);

$logs = $service->getLogs([
    'type' => 'admin',          // Filter by category
    'action' => 'updated',      // Filter by event
    'causer_id' => 5,           // Filter by user
    'subject_type' => Role::class, // Filter by model
    'subject_id' => 5, // Filter by model
    'from' => '2024-01-01',     // Date range
    'search' => 'critical'       // Keyword search
], 20); // 20 per page

Categorization

The system separates logs into Admin and User logs automatically by checking the causer model type.

Adding a New Type (e.g. Supplier)

If you have a third type of user like Supplier, you can easily define it in their model:

class Supplier extends Model {
    use LogsActivity;

    // This will tag all actions by suppliers as 'supplier'
    public string $activityLogType = 'supplier';
}

Now you can filter specifically for them in the API: ?type=supplier

  • If the causer is an Admins instance, it's tagged as admin.
  • Otherwise, it defaults to user.
  • You can override this per-log or per-model.

Configuration

Customize the system via Config/activity_log.php:

return [
    'table_name' => 'activity_logs',
    'ignored_attributes' => [
        'password', 'remember_token', 'otp_pin', ...
    ],
    'default_causer' => \Modules\Admins\Models\Admins::class,
];
